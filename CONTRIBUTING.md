# Contributing to Kenzai Intelligence

Thank you for helping improve a Kenzai project.

## Before contributing

- Use an existing issue when one describes the work; otherwise open a focused issue first.
- Never include credentials, private customer information, production data, or confidential documents.
- Keep changes scoped, explain the operating problem, and include verification evidence.
- Preserve human approval and security boundaries when changing automation behavior.

## Pull requests

A useful pull request includes:

- the problem and intended outcome;
- the approach and important tradeoffs;
- tests or live verification appropriate to the changed boundary;
- screenshots for material interface changes; and
- documentation updates where behavior or setup changes.

All contributions are subject to review, security checks, and repository-specific instructions.
